CIP-015 R1Supports our current work

#### Monitor and evaluate anomalous activity inside the ESP

INSM applies to networks inside the Electronic Security Perimeter of high impact BES Cyber Systems and medium impact systems with External Routable Connectivity. Entities must detect and evaluate anomalous network activity. Effective Oct 1, 2028, control centers first. [56](https://hollow-flame-f2tf.here.now/#src-s56 "CIP-015-1 standard text: Requirements R1 (INSM), R2 (retain anomalous-activity data), R3 (protect from deletion or modification)") [29](https://hollow-flame-f2tf.here.now/#src-s29 "CIP-015-1 (effective date 10/01/2028)")

What it means Hot, searchable data in Splunk Cloud for ES Premier detections and analyst evaluation; Cyber Vision and IE sensors as the INSM collection point.

CIP-015 R2Supports our current work

#### Retain anomalous-activity data until the action is complete

Entities retain INSM data tied to anomalous activity at least until the R1.3 evaluation is complete. They choose which data types to discard quickly, keep briefly or keep longer. Full packet capture that is not relevant to anomalies does not have to be kept. [56](https://hollow-flame-f2tf.here.now/#src-s56 "CIP-015-1 standard text: Requirements R1 (INSM), R2 (retain anomalous-activity data), R3 (protect from deletion or modification)") [57](https://hollow-flame-f2tf.here.now/#src-s57 "Petition for approval of CIP-015-1 (retention by data type; R3 protective controls incl. isolated INSM network)")

What it means A tiered retention policy per data type: metadata and detections hot, full-fidelity flows and PCAP in low-cost storage, evidence packages archived.

CIP-015 R3Supports our current work

#### Protect INSM data from unauthorized deletion or modification

NERC lists protective and detective controls: access limited to authorized personnel, systems with built-in integrity safeguards, and segmenting the INSM system onto an isolated network separate from the monitored BES Cyber System. [56](https://hollow-flame-f2tf.here.now/#src-s56 "CIP-015-1 standard text: Requirements R1 (INSM), R2 (retain anomalous-activity data), R3 (protect from deletion or modification)") [57](https://hollow-flame-f2tf.here.now/#src-s57 "Petition for approval of CIP-015-1 (retention by data type; R3 protective controls incl. isolated INSM network)")

What it means Role-based access with audited deletes, immutable copies for retained evidence, and an INSM data path that does not share trust with the OT network it watches.

CIP-004-7 / CIP-011-3Supports our current work

#### BCSI may live in the cloud, with key management choices

Since Jan 1, 2024, NERC standards accommodate BES Cyber System Information in cloud services. With entity-managed keys the provider cannot decrypt BCSI, which simplifies evidence. With mutually managed keys, provider personnel fall into the entity access program. [58](https://hollow-flame-f2tf.here.now/#src-s58 "CIP-011-3 Information Protection (BCSI), mandatory 01/01/2024") [59](https://hollow-flame-f2tf.here.now/#src-s59 "Security Guideline: Primer for Cloud Solutions and Encrypting BCSI (entity-managed vs mutually managed keys)") [60](https://hollow-flame-f2tf.here.now/#src-s60 "Implementation Guidance: CIP-004-7 R6 and CIP-011-3 R1, cloud solutions for BCSI")

What it means Decide early whether INSM data in Splunk Cloud or S3 counts as BCSI, and who holds the keys. This drives where each tier can live.

Splunk Cloud DDAASupports our current work

#### Splunk-managed archive for long-term evidence

Dynamic Data Active Archive keeps expired index data in a Splunk-managed archive for up to 3,650 days. Restores land within about 24 hours and stay searchable for 30 days. Sold in 500 GB increments with 10% extra DDAS for restores. [61](https://hollow-flame-f2tf.here.now/#src-s61 "Store expired Splunk Cloud Platform data in a Splunk-managed archive (DDAA, up to 3650 days, restore within 24h, searchable 30 days)") [65](https://hollow-flame-f2tf.here.now/#src-s65 "Details of DDAS and DDAA (optional subscription, 500 GB increments, +10% DDAS for restores)")

What it means Fits R2 evidence that must survive audits without staying in searchable storage.

Splunk Cloud DDSSSupports our current work

#### Customer-owned S3 storage for aged index data

Dynamic Data Self Storage moves expired data to a bucket Dominion owns. Federated search over DDSS datasets is now documented through a Splunk-native DDSS data catalog in AWS, including restores from Glacier storage classes. [62](https://hollow-flame-f2tf.here.now/#src-s62 "Run federated searches over DDSS datasets: Splunk-native DDSS data catalog in AWS")

What it means Dominion controls the bucket, keys and retention lock settings, which strengthens the R3 and BCSI story.

Ingest Processor to S3Supports our current work

#### Route full-fidelity data to S3 at ingest and search it in place

On Splunk Cloud 10.4.2604 and later, an Amazon S3 dataset can serve both as an Ingest Processor destination and as a Federated Search source. Constraint: the destination bucket must not have Object Lock turned on. [63](https://hollow-flame-f2tf.here.now/#src-s63 "Create an Amazon S3 dataset for Ingest Processor pipelines (10.4.2604+, routing plus federated search; bucket without Object Lock)")

Our recommendation Recommendation: pair the write bucket with versioning and replication to a separate Object Lock bucket, so R3 immutability holds without breaking the pipeline.

Federated Search for S3Supports our current work

#### Search Parquet, JSON or CSV in S3 without re-ingesting

Federated Search for Amazon S3 reads CSV, newline JSON, Parquet, ORC, Avro and XML, including data written by Edge Processor and ingest actions. DDSS format needs the DDSS dataset path instead. [64](https://hollow-flame-f2tf.here.now/#src-s64 "About Federated Search for Amazon S3 (Parquet, JSON, CSV; Edge Processor and ingest actions output)") [55](https://hollow-flame-f2tf.here.now/#src-s55 "Overview of the federated search options for the Splunk platform")

What it means Analysts query cold INSM data from the same ES and SPL workflow, so access to storage is re-architected without a second tool.
